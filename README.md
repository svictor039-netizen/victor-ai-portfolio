# Victor AI Portfolio

Персональный AI-портфолио сайт Виктора: реальные AI-проекты, AI-агенты, RAG-консультанты, AI-сервисы, автоматизация, n8n/API-интеграции и коммерческие кейсы.

## Главный проектный документ

Основное руководство по проекту и последующим задачам для Codex:

`VICTOR_AI_PORTFOLIO_MASTER_BRIEF_v2.md`

Перед существенными изменениями архитектуры, контента, SEO, AI-агентов, аналитики, лидогенерации или автоконтента Codex должен сверяться с этим документом.

Сайт должен быть:

- быстрым;

## Правила работы Codex

Codex должен:

1. Сначала читать `VICTOR_AI_PORTFOLIO_MASTER_BRIEF_v2.md`.
2. Работать только в рамках текущего ТЗ.
3. Не модифицировать другие проекты.
4. Не устанавливать пакеты без необходимости или отдельного разрешения.
5. Не придумывать метрики, результаты и READY-статусы.
6. Не выполнять deploy без отдельного указания Виктора.
7. После этапа давать короткий отчёт:
   - что изменено;
   - какие файлы затронуты;
   - какие проверки выполнены;
   - что осталось сделать.

### Что уже готово

- Публичный статический сайт с понятным Hero и каталогом; локальная сборка содержит восемь отдельных страниц кейсов, production пока содержит шесть.
- Честные статусы, доказательства, ограничения и отсутствие выдуманных метрик.
- Коммерческий раздел AI-агентов Front Office / Back Office и понятные CTA.
- Основной контент доступен в HTML; критические действия не зависят только от hover.
- SEO-основа создана: централизованные metadata, маршруты `robots.txt` и sitemap, управляемый флаг индексации.

### Что мешает считать MVP завершённым

- Нет рабочего Telegram/формы, реального лид-магнита и базовой аналитики.
- Новая flagship-тройка ещё не опубликована; для Travel MCP Agent отдельно не хватает локального исходного кода и независимого подтверждения авторства реализации.
- Production закрыт от индексации, canonical отсутствует, sitemap пуст.
- Нет `/blog`, SEO-шаблона статьи и реализованного контура «черновик → проверка → публикация».
- Не проведена актуальная production-проверка скорости на mobile/desktop.
- Для Lead Intelligence и Analytics Agent пока нет lead/event-контрактов и неблокирующего backend-контура.

### Следующие задачи по приоритету

**P0 — обязательно для сдачи / первого релиза**

1. Опубликовать и проверить в production три подготовленных flagship AI-кейса; отдельно добавить допустимое подтверждение роли Виктора в Travel MCP Agent, если оно существует.
2. Подключить подтверждённый Telegram или рабочую форму и проверить доставку обращения end-to-end.
3. Сделать реальный лид-магнит с понятной ценностью и рабочей выдачей/доставкой результата.
4. Подключить базовую аналитику и ключевые события CTA, проектов, агентов, лид-магнита и обращения.
5. Настроить production origin и canonical, открыть индексацию после удаления блокирующих заглушек, наполнить sitemap всеми индексируемыми страницами и повторно проверить metadata.
6. Создать `/blog` и SEO-шаблон статьи; зафиксировать состояния контента и editorial gate между генерацией, проверкой и публикацией.
7. После следующего deploy провести Lighthouse/production QA на mobile и desktop, проверить Core Web Vitals, доступность основных маршрутов, `robots.txt`, sitemap, canonical и индексируемость.

**P1 — желательно после P0**

1. Ввести единый контракт lead capture и событий: источник, UTM/referrer, просмотренные кейсы/агенты, ключевые клики, согласие и статус доставки.
2. Подготовить неблокирующую очередь/endpoint и интерфейсы для будущих Lead Intelligence и Analytics Agent без подключения выдуманной автоматизации.
3. Дополнить биографию, подтверждённые контакты, роль в проектах и разрешённые публичные доказательства.
4. Подключить Search Console/Вебмастер и мониторинг ошибок индексации после открытия сайта поисковым роботам.

**P2 — развитие после запуска**

1. Подключить Lead Intelligence, квалификацию и Telegram-отчёты Виктору с разделением фактов, предположений и ненайденных данных.
2. Запустить Analytics Agent с агрегированными выводами и рекомендациями, а не только сырыми метриками.
3. Развить независимый контентный pipeline: research/SEO → draft → validation → editorial approval → publish → distribution → content analytics.
4. Расширять страницы услуг, агентов, кейсов и SEO-кластеры только по подтверждённому спросу и данным после запуска.
