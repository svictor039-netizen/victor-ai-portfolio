Новый проект на Astro, React и Tailwind CSS. Визуальная система — первая версия,
не окончательно утверждённый дизайн. Исходные research-документы сохранены.

## Запуск

Из `D:\AI Workflows\victor-ai-portfolio`:

```powershell
npm run dev
npm run check
npm run build
npm run preview
```

Development по умолчанию: http://127.0.0.1:4321/.
При занятом порте Astro напечатает фактически выбранный адрес.
`npm run preview` проверяет уже созданный `dist/`.
Зависимости фиксируются в `package-lock.json`; для чистой установки — `npm ci`.

В ограниченной среде перед командами можно задать
`$env:ASTRO_TELEMETRY_DISABLED='1'`, чтобы Astro не создавал глобальную
конфигурацию telemetry. При проверке использовалось именно это окружение.
Astro 7 запускает сервер отдельным процессом. Остановка development:
`npm exec -- astro dev stop`; остановка preview: `npm exec -- astro preview stop`.

## React и KokonutUI

У Gradient Button нет зависимости от Next.js или Motion. Источник получен через
настроенный shadcn MCP и включён локальным TSX-файлом, с атрибуцией и адаптацией.
Компонент рендерится на этапе сборки: директивы `client:*` отсутствуют.
Для кнопки-ссылки hydration не нужен; React runtime не должен загружаться
посетителю. React integration оставлена для обоснованных islands следующих ТЗ.
Card Flip, Smooth Tab, Smooth Drawer и библиотечный Bento Grid не установлены.
Сетки реализованы обычным CSS.

Совместимость и способ настройки сверены с официальной документацией:
[Astro React](https://docs.astro.build/en/guides/integrations-guide/react/),
[Tailwind для Astro](https://tailwindcss.com/docs/installation/framework-guides/astro).
Tailwind подключён через Vite plugin, а не устаревшую Astro Tailwind integration.

## SEO и будущие URL

Пока домен не подтверждён и контент остаётся черновым, используется
`noindex, nofollow`, robots запрещает обход, sitemap содержит пустой urlset.
Canonical и `og:url` не подменяются выдуманным или локальным доменом.
После утверждения домена задайте `PUBLIC_SITE_URL=https://ваш-подтверждённый-домен`
в локальном `.env` или окружении сборки. Сборка валидирует HTTPS origin.
Индексация включается отдельно через `PUBLIC_ALLOW_INDEXING=true` только после
замены заглушек и подключения настоящих контактов; требуется новая сборка.
При этом sitemap включает `/`, canonical и OG URL получают единый origin.
OG image пока отсутствует: готового реального изображения нет.

Новые содержательные маршруты по концепции: `/projects/<slug>/`, `/ai-agents/`,
`/services/<slug>/`, `/blog/<slug>/`. Они пока не созданы и не включены в sitemap.
Для новых опубликованных маршрутов нужно обновлять `publicPages` в site.ts.
404 отдаёт отдельную страницу; при hosting позже нужно сохранить HTTP 404.

## Честные ограничения каркаса

Три проекта — примеры структуры, не отобранные flagship-кейсы. Результаты,
production-статусы и метрики не заявляются. CTA «Посмотреть кейс» раскрывает
статус подготовки; он не ведёт на несуществующую страницу.

Четыре агента — примеры направлений разработки, не готовые продукты.
Три карточки блога — будущие темы, без фиктивных дат, авторства или статей.
Бриф показывает вопросы, не собирает ответы. Telegram и сообщение раскрывают
честное уведомление о неподключённом канале. Отправки, CRM, Lead Intelligence,
аналитики, AI SDK, автоконтента и внешних запросов в интерфейсе нет.
Биография, портрет, подтверждённые контакты и screenshots пока не заполнены.

Растровые изображения пока не добавлены. При добавлении: явные width/height,
оптимизированный формат, responsive sizes и `loading="lazy"` ниже hero.
